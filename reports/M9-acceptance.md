## 4. 与上游的有意差异（都写在 `docs/DECISIONS.md`）

1. **终局**：真正进入 `finished` 并计算胜者（上游从不进入该状态，只能手动 Stop）。
2. **同步模型**：主机每次动作后广播完整快照 + `seq`（上游是增量事件回放），换取"任意时刻可收敛、重连只要一份快照"。
3. **持久化**：版本化信封、逐键校验（上游任一键损坏即丢弃整份存档）。
4. **曲目身份**：`(专辑, 曲目)` 二元组（上游是手抄路径字符串）。
5. **字体**：只分发 OFL 的 Inconsolata；正文用本机 Whitney，之后按
   苹果默认 → 鸿蒙默认 → 微软雅黑 → Noto CJK 回退（D15）。
6. **本地化**：比上游更彻底 —— 上游的判定状态文案与大厅字段是英文硬编码，这里全部走 `t()`
   （英文侧仍保留上游的枚举名，见 D16）。
7. **主题**：整体照搬上游深色色板（页面 `#141414` / 纸面 `#262626`）；上游的 `mainTabBackground`
   外层容器不再重复套一层（面板自带 Paper）。

## 4.1 对局内播放（D17，晚于首轮验收补上）

首轮验收漏了"对局时到底有没有声音"：音乐原本只跟轮播队列走，开局后**静音**。现在音乐由对局驱动 ——
倒计时响铃（合成铃）、回合开始播当前角色的曲子、停局/终局停；对局中的选曲种子由已同步的
`(turnSeq, currentKey)` 派生，两端必然同一首（E2E 断言两端 `audio.src` pathname 相同）。
对局期间锁住其它页签（上游行为）。切歌不再中断播放（上游 `loadeddata` 续播语义）。

## 4.2 开局洗牌（D19，晚于首轮验收补上）

开局会把轮播顺序洗一遍并记下本局种子（上游 `createPlayingOrder(..., true)` 同样洗牌），
选曲种子由 `(gameSeed, turnSeq, currentKey)` 派生：连开四局实测四个不同开局角色、四首不同首曲；
联机两端种子随快照同步，E2E 仍断言两端播放同一首。

## 4.3 动效（D21，晚于首轮验收补上）

播放页与游戏页的过渡值逐条照抄上游：卡片 `transform/background-color/filter 0.3s` + hover 抬起 10%、
牌桌卡牌层绝对定位常驻 + `left/top 0.4s`（补满/换位/交换/改行列时牌会滑过去）、
播放页"接下来"改成上游的重叠牌堆（`left 0.5s ease-in-out`、同角色叠 80%/角色间叠 20%、
卡宽 `min(20vw,150)`、点击＝临时跳过）、当前角色多张卡面叠放 + 切歌滑入、提示条淡入。
三处差异：切歌用滑入替代上游的 121 张常驻轮播、牌堆从当前角色起排并标 `selected`、拖拽用浏览器原生拖影。

## 4.4 视觉收尾（D22，用户反馈后）

卡片默认**不带纸框/底色**（`bare`：透明底 + 状态描边圈），牌桌格子不再给有卡的位置描边铺底，
游戏盘的卡槽不做悬浮动效（只在真拖拽时给虚线落点），播放页牌堆与游戏选卡区都能横向滚动，
牌堆顶部留白保证抬起动画不被裁切也不压文字。抢对/抢错的反馈因此从整卡染色改为描边圈。

## 4.5 视觉收尾二（D23，用户反馈后）

卡牌只保留**一层白底**（无纸框无投影，槽位不铺底）；播放页牌堆**等距不重合**且可横向滚动，
上方大卡面恢复单张；`color-scheme: dark` 让原生滚动条与深色主题一致（上游同款）；
牌桌区域在容器内**居中**、超出时可滚动。

## 4.6 游戏卡槽的滚动方式（D24，用户反馈后）

游戏界面的未使用卡牌区改成**上游实现**：卡片叠 30% 排成一条与牌桌同宽的长条，下方一个 MUI `Slider`
（上游的 "Card Selection Slider"，`min 0/max 1/step 0.001`）拖动即平移整条卡槽，
滑块在卡条下方、不遮挡卡片；该区域的原生横向滚动条由滑块取代。播放页牌堆维持不重叠 + 原生滚动条。

## 4.7 选卡区统一（D25，用户反馈后）

"卡条 + 下方滑块"抽成共享组件 `CardStrip`：播放页与游戏选卡都用它，卡片**等距不重叠**（间距 6px），
滚动一律由滑块完成（不再用原生横向滚动条）；两处的 hover 都**只变背景色、不做抬位移**。

## 4.8 选卡区外框与滑块性能（D26，用户反馈后）

两处选卡区域都套上外框并居中；平移从"逐卡改 `left`"改成"整行一个 `translateX`"，
拖动过程直接写 DOM、松手才落 React 状态，卡片组件 `memo` 化 —— 实测拖滑块 30 步
**卡片节点 0 次样式变更**（原来每步要改上百个节点）。

## 4.9 滑块与外框细节（D27，用户反馈后）

外框左右内边距加到 12px，滑块推到两端拇指不再越界；选卡显示区（`overflow: hidden` 那层）改用与卡牌
相同的 6px 圆角，滚动到边界时被裁掉的卡片不再出现直角。

## 4.10 滑轨与卡片边缘对齐（D28，用户反馈后）

滑轨改成自绘、与卡片显示区同宽，MUI 滑块本体两端各内缩一个拇指半径：
滑轨端点、拇指外缘（推到两端时）、卡片外缘三者落在同一条竖线上（实测偏差 0px）。

## 4.11 交换动画与滑块光圈（D29，用户反馈后）

卡牌层改为按卡面 key 稳定排序渲染，交换时不再有 DOM 重排，两张卡一起平滑滑过去（并在换位瞬间
抬到最上层 + 轻微放大）；滑块只屏蔽鼠标态（hover/按压）的光圈，键盘 focus-visible 提示保留。

## 4.12 两处选卡滑块一致性（D30）

播放页与游戏选卡的滑块共用 `CardStrip`：逐项比对 computed style 只有区域宽度不同，样式完全一致；
E2E 增加断言把两者锁成一致，防止以后单边改动造成漂移。

## 5. 已知限制

- **跨机器（不同物理机）联机未实测**：本机已用 chromium↔firefox + 本地 PeerJS 信令 + 真 WebRTC 打通；
  跨公网还依赖公网 STUN/TURN（当前用 PeerJS 默认配置，即 Google STUN），极端 NAT 下需要自建 TURN。
- E2E 为了在容器里建 WebRTC 连接，关掉了浏览器的 mDNS 候选混淆（见 `docs/DECISIONS.md` §D13）；
  真实环境不需要。
- 卡面素材不随仓库分发，首次加载需联网；离线使用需自行放入 `public/cards*/`。
- 秘封倶楽部 CD 的"第 N 作"序号在 THBWiki 与 MusicBrainz 之间有分歧，因此只作展示顺序，不作键。
- TH20（東方錦上京）的 14 条已用线上 Music Room 判定，但仍建议在后续版本与官方资料复核。
- 游戏页**已实现拖动放置**（D20）：未使用卡拖到指定牌位、牌位之间拖动即交换、拖回未使用区即拿出来、
  交牌阶段拖到对手空位即指定交牌；点击路径保留（点未使用卡落第一个空位、点牌库卡拿回来）。
  与上游差别只在渲染方式：上游是 canvas 自绘 + 卡牌跟随光标，这里是 DOM + 浏览器原生拖影。
  键盘快捷键对齐上游（本来就没有）。
