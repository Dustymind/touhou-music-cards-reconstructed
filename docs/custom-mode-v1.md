# 自定义模式契约 v1（卡名 · 卡面 · 曲目一一对应，数据全靠使用者自己的源）

**状态：已实现**（D156–D161）。对象：第三个音乐模式「自定义」（内部 id `custom`）的**数据来源**、
**源清单形状**、**选曲语义**与**联机口径**。

目的：这个模式**自带数据集恒为空** —— 卡名/卡面/曲目全部来自使用者自己托管的一份 `manifest.json`，
应用只负责把它读进来、画出来、连起来。于是"加一张卡"= 改自己的清单，**主仓库一个字都不用动**。

前置：D145（源可以在运行时提供曲目表）、D140/D141（源地址与相对解析）、D144（媒体版本号）；
计划与逐轮落地记录在仓库外 `THIRD-MODE-PLAN.md`，决策见 `docs/DECISIONS.md` D155–D161。

---

## 1. 三段式（谁提供什么）

| 角色 | 提供什么 | 不提供什么 |
|---|---|---|
| **应用**（本仓库） | 读取、校验、渲染、联机；**一套空兜底数据集**（`public/data/custom/`，0 角色 0 专辑） | 任何卡名 / 卡面 / 曲目 / 音频地址 |
| **使用者的源**（`manifest.json` + 素材） | 卡表（一张卡 = 一个卡名 + 一张卡面 + 一首曲目）、素材地址、可选的响度表 | 任何应用逻辑 |
| **数据仓库**（独立仓库，`touhou-music-cards-custom-data`，挂在 `data/custom`） | **只提供工具**：把手写的卡表抓成素材并生成清单；**仓库里不含任何卡数据、也不放文档**；**不是应用的构建输入** | 卡数据本身；应用不 import 它、`data:build` 不读它 |

**不依赖主仓库构建**（Q2）：`data/custom` submodule 初始化与否，`pnpm data:build` / `data:check`
的输出**逐字相同**（有守卫用例：把"曲包真源在不在"这个开关翻过来跑两遍比文本；另有手工验证：
把 `data/otomads` 与 `data/custom` 分别挪走跑 `data:check` —— 都无漂移）。

## 2. C1 数据集来源

模式 3 的**自带数据集恒为空**（0 角色 / 0 专辑 / 1 条地址为空的源）。有源链接且清单合法时，
运行时用清单**整体重建**该模式的数据集；取不到（没填 / 源挂了 / 形状不对）⇒ 回到空兜底，
**不报错**，界面提示"必须填写自定义源链接"。

## 3. C2 源清单形状（严格校验，坏形状整份拒绝）

```jsonc
{
  "schema": 1,                       // 必填，仅认 1
  "mode": "custom",                  // 必填，必须等于 "custom"
  "cards": [                         // 必填、非空；一项 = 一张卡（1:1 在形状里就写死）
    {
      "id": "alice-01",              // 可选；缺省 = 由 (卡名|专辑|曲名|卡面) 派生的稳定 key
      "name": "卡名（显示名）",        // 必填、非空
      "cover": "cover/alice-01.jpg", // 必填；**相对清单目录** 或 **http(s):// 绝对直链**
      "audio": "media/alice-01.mp3", // 必填；同上两种形态
      "revision": "…",               // 可选：这一首的版本号（拼进音频 URL 的 `?v=`）
      "album": "专辑名",              // 必填、非空
      "author": "作者名",             // 可选；空 ⇒ 不进作者开关列表
      "title": "曲名",                // 必填、非空
      "source": "https://…"          // 可选，仅留档/署名
    }
  ],
  "revision": "…",                   // 可选：整表兜底版本（每张卡没写 `revision` 时用它）
  "loudness": "loudness/custom.json" // 可选：相对清单自身（D139 口径）
}
```

**校验规则**（`src/data/customManifest.ts`；任何一条不满足 ⇒ 整份 `undefined`，走空兜底，绝不半信半疑地用）：

1. `schema === 1`、`mode === "custom"`；
2. `cards` 非空；每张卡 `name/album/title/cover/audio` 是非空字符串，`author/id/source/revision`
   若存在须非空；
3. `id` 若写了必须**唯一**；没写就用内容哈希派生（跨端同值、与数组顺序无关）；
4. **不要求 `(专辑, 曲名)` 唯一**：同名曲目允许，两张卡也可以共用一首 —— 后者会被
   `songConflicts` 判为互斥（一局里只允许一张在场），这是**有意的**；
5. 每张卡的 `audio` 必须能解析出地址（相对 ⇒ 按清单目录拼成绝对；绝对 ⇒ 原样）——
   **缺 `audio` 就是整份不合法**（宁可整份不生效，也不要"看得见、点不响"）。

## 4. C3 卡面与音频地址

生效图集 = 代码里的**合成图集**（`CUSTOM_CARD_SET`：`{ id: "custom-source", mode: "custom",
sourceOnly: true, dir: "", origins: [], localPrefix: "./", ratios: ["16x9","4x3","original"] }`）
**+ 用户选的档位**（`cardSet.ratio`，由 `resolveCardSet(..., preference)` 落上去，D165）：

- `cardsets.json` 里的任何图集在这个模式下**都不列出**，用户存下的 `cardCollection` 偏好**被忽略但不改写**；
- 每卡恰好一张卡面（`covers.length === 1`），`cardCount` / `maxCardCount` 恒为 1；
- **卡面形状 = 三档**（`"16x9"` **默认** / `"4x3"` / `"original"` 常规，设置页「卡面设置」里切，
  D165），**这个模式统一、没有逐卡的选择**。渲染侧一律用 `theme/cardRatio.ts` 的
  `cardAspectRatio(cardSet)` 取 —— `CharacterCard`（`aspect-ratio`）、`CardStrip`（可视窗口高）、
  `DeckGrid`（卡槽高 + 彩蛋框）、`UnusedCards` / `UnusedCardsTray`（占位与档位）、
  `UpcomingFan`（牌堆高）全部跟着它走。内置六套原版图集**不能换档** ⇒ 永远是原比例 703:1000
  竖版、`object-fit: contain`，行为逐字不变；数据侧若要写 `ratios`，值必须是认得的档
  （`validateCardSets` 会拦下非空校验以外的非法值）。
- 相对路径在**校验阶段**就按清单目录解析成绝对地址（`sourceRelativeUrl`）；绝对 URL 原样用；
- 卡面缺字段 ⇒ 整份清单不合法（不出现"空卡面"）；运行时图片 404 ⇒ 走 `CharacterCard` 现有占位行为；
- **`cover` 只写一条链接**（D167）：清单里就是一个非空字符串（相对清单目录的路径，或 `https://` 直链），
  在校验阶段解析成绝对地址、存进 `card` / `covers`（这个模式恰有一张）。
  源应当给**原版无修改**的那张图 —— 不要加 `@<宽>w_<高>h_1c` 这类服务端裁切/缩放参数：
  **画幅与裁切由前端按用户选的档位做**（`object-fit: cover`），数据侧只有一种形态。
  对象形态（旧的逐档表）现在是**坏数据**：整份清单不合法。
- 卡面按 `object-fit: cover` 铺满当前档位的框：比例正好就不裁，比例不对就居中裁掉多余的部分
  （**一张原图供三档使用**：比例不对也不会拉伸，只是裁掉多余的部分）；
- **音频同理**：`audio` 也在校验阶段解析成绝对地址，按**每张卡**存进数据集（`CharacterRecord.audio`，
  与 `music` 一一对应），播放时**不再走 `(专辑, 曲名)` 查表**；版本号用 `revision` 拼 `?v=`。

## 5. C4/C5 选曲语义

**预设（C4）**：只有**专辑三元 + 作者三元**（没有类别开关、没有秘封碟）：

```
启用 = 专辑 !== "off" && 作者 !== "off"
```

即：**默认（两维都 `unset`）= 全开**；**任一维 `off` 一票否决**；`on` 只压"另一维未配置"；
**没有作者的卡**只看专辑三元（作者维度对它不适用）。

**仅单曲模式（C5）**：只有逐曲（= 逐卡）禁用表；禁用的卡**不进轮播、也不进卡池**
（`AppShell` 算一份可用集合，同时喂队列与游戏页的 `cardKeys`）；无总开关、无手选；存档按模式分键。

## 6. C6 哈希与协议

第三个数据哈希 `custom` 由**应用**算（`customHash`，冻结在应用里；空兜底也有稳定值）。覆盖：
卡 key / 卡名 / 顺序 / 卡面 URL（**解析后的绝对串**，一条）/
专辑（key/name/order/kind/pack）/ 作者 / 曲名。
**不覆盖**：**音频地址与版本号**（同 D145：换 CDN/换宿主不该把两端拆开）、清单来源 URL、页面来源，
以及 **"用户此刻选了哪一档"**（16:9 / 4:3 / 常规都是显示偏好，不是数据 ——
两端各选各的照样能握手，D165）。

协议 **v5**（`docs/protocol-v1.md`）：`DataHashes` 三项、`MusicModeWire` 三项、
`SessionConfigWire.customSourceUrl`、`hello.customSourceUrl`、`reject.customSourceUrl`。

## 7. C7 空源与联机采用（F3）

- 链接为空 ⇒ **不发请求、不报错**；模式 3 显示 0 张卡 + 一行"必须填写自定义源链接"；
- **重置 = 清空**（与 D140 的"回默认值"不同：这个模式的默认值本来就是空）；
- 生效值优先级：**主机下发的会话级覆盖 > `?customsource=` > 存档值**；两个覆盖都**不落盘**；
- 联机：主机在 `musicMode === "custom"` 且自己有源时，把源随 `reject` 发过去 ⇒
  客户端本地空**自动采用**、有别的值**问用户**；采用**只在本会话生效**，`leave()` 即恢复自己的源；
- 自动重发 hello **只重试 1 次**（避免"采用 → 还是不同 → 再采用"的死循环）。

## 8. 地址形态（同源与裸主机）

`normalizeManifestUrl` 只给**裸主机**补 `http://`（`127.0.0.1:8012` / `cards.example.com/music/`），
**相对当前页面**的三种写法原样保留：前导 `/` 的根路径、带目录的相对路径、只有文件名的 `manifest.json`。
理由：使用者完全可能把清单放在**应用自己的站点**上（同源静态托管），这时它就是一个普通相对地址。

## 9. 界面

- 「音乐源」分区在模式 3 下只渲染**一行**：输入框 → 重置 → 应用，外加状态（**卡数**，不是 `entries.size`）、
  红色必填提示、"清单不合法"、以及房内的"主机在用：…"；
- 「卡面设置」分区（D164 从「卡面图集」改名，三个模式同一个分区、同一个标题）= 一行只读说明
  （图集在该模式下不可用）+ **三档画幅**（常规 / 16:9 / 4:3，分段控件）+ 三张示例卡
  （示例卡走同一个 `cardFace`，所以切一下就能看到牌桌上真正会画的那张）+ 存档键
  `session.cardRatio`（落盘、逐键校验、`""` = 跟着图集的默认档）；
- 「音乐选择预设」= 专辑三元 + 作者三元；「仅单曲模式」= 逐卡禁用列表；
- 间距与尺寸全部沿用既有 MD2 常量（8dp 栅格 / 32dp small 按钮 / 40dp 行高），一个都没改。
