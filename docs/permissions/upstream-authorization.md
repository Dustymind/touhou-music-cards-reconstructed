## 一处残余风险（已由项目作者判断并接受）

截图没有逐字写出「可按 MIT 再许可」——字面上覆盖的是"你自己 fork 与部署"，
而 `LICENSE` 里的 MIT 是**向第三方**授权。

项目作者的判断：对方「我随便」的表述已足够宽泛，且本项目的实际用法
（fork + 自行部署，对方原话「你 fork 完了自己部署也行」）正是对方明确点头的场景，
因此按 MIT 发布成立。

留这条只为可追溯，不是待办。若日后想要更硬的凭据，补一句即可：
「我打算把这份 fork 按 MIT 开源，可以吗」。

## 代码关联性复核（2026-09-29）

"部分代码移植自上游"这句量过一遍。方法：取上游 `main` 的 HEAD（`af8b0aa`，与本地记录一致）的
`app/**` 全部代码文件，逐个找本仓库对应实现，去空行/注释/纯括号行后做**行级**比对：

| 指标 | 结果 |
|---|---|
| 逐行重合（上游某行在本仓库出现过） | 按文件 0–25%；21 个对应文件合计 **515 / 6237 行 ≈ 8%**（口径越松越高，纯括号行会明显抬高） |
| **最长连续重合**（判"抄没抄"看这个） | 全部 ≤ **6 行**；长的三处都是**数据/文案**：`Localization.ts` 的文案表（6 行，含中文译文）、`page.tsx` 的彩蛋台词（5 行）、`Cheat.ts` 的 HSV→RGB 小算法（5 行） |
| 对局核心 | 上游 `GameJudge.ts`（1431 行）↔ `src/game/rules.ts`：最长连续重合 **1 行** |
| 规模 | 上游 `app/**` 21 个代码文件；本仓库 `src/**` 88 个（net/ data/ music/ store/ 等都是新写的） |

结论：**以重写为主**（读了上游 + 先写规格笔记再实现），沿用的是少量文案、彩蛋台词与零散片段，
不是成块复制。上面那条"残余风险"的适用范围就是这些沿用片段，而不是整个 `src/`。
